# 按笔记体写学习笔记

笔记正文是实验记录。从一次具体的麻烦写起，按手里的操作往下记，判断留在当场，写到能用就停。

技术结论、命令、路径、IP、报错字符串保持用户给出的原样。改的是叙述顺序，以及哪些句子留下。

## 成稿顺序

1. 第一句写这次碰到的失败、终端输出，或为什么现在要记（给谁讲过、哪台机器、哪次场合）。
2. 按操作往下写：路径、命令、屏幕上的输出。同一件事不换一章再讲。
3. 原因只留在当时看错的那一处，紧挨着那条命令或那行输出。
4. 停在最后一条验证和实际看到的输出。

用户没提供的现场不要编。原文里已有的判断和错字保留，不要另加「好像」「踩了个坑」，也不要故意写错。

## 草稿长这样时，改成笔记

| 草稿 | 改成 |
|---|---|
| 「本文按 A 和 B 分开写」「本文旨在梳理」 | 删掉。用这次的失败或场合起笔 |
| 文首「先分清 / 总览」表 | 删掉表。差别放进后面第一次用到它的那条命令 |
| 两个环境各有同名小节，讲同一件事 | 只在先碰到的地方写完整。另一处只留该环境特有的路径和命令 |
| 每段都是「事实，因为原因。所以要这样做」 | 配置和输出写完就停。原因只留看错过的那一处 |
| 文末「总结 / 对照 / 怎么选」把前面再列一遍 | 删掉。验证输出就是结尾 |
| 「应看到 200」「成功标志是」 | 写成终端里那一行输出 |
| 一条命令带上后来才加的全部参数 | 先写当时跑的那条，下一句再写加上的参数 |

## 例子

草稿：

> 本文按本机 Docker Desktop 和实验宿主上的 Docker 引擎分开写。两边的「本机地址」不是同一个东西，配错就会出现容器里访问不了外网。

笔记：

> 容器里访问 `127.0.0.1:7897` 会立刻失败，`curl` 报 `Couldn't connect to server`。这个地址指向容器自己。

## 不要动的正文

用户声明搬运、贴官方文档，或只要建文件和格式整理时，保持原文。笔记体只在用户要求写、改，或降低 AI 味时用。
